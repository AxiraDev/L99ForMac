# Происхождение проекта

Дата исследования: 20 октября 2026 года.

## Метод

Локально исследован предоставленный пользователем установщик `AULA L99-EN Driver-1.0.1.6.exe`.

SHA-256 установщика:

```text
8090266d88a22c5d1c31b83ec30474f8416b27cbf69b83bc3260210da2276fdf
```

Архив Inno Setup распакован без установки. Windows-программа и обновления прошивки не запускались. Основная программа исследована статически; для RGB, real-time data, музыкальных данных и полного GIF-контейнера изолированные преобразователи исполнены в эмуляторе x86, с заменой операций ввода-вывода заглушками. Эмулятор не имел доступа к USB.

Новые файлы Rust и Swift написаны по сведениям о формате обмена и функциях. Имена переменных, структура исходников, интерфейс, тексты и отрисовка клавиатуры созданы для этого проекта. Полная функциональная эквивалентность не подтверждена.

Это **не строгий clean-room-процесс**: тот же участник изучал скомпилированную программу и писал новую реализацию. Подменять этот факт заявлением о независимых командах нельзя.

## Материалы в публичной части

- Rust: собственная реализация сериализации документированных сообщений.
- Swift / SwiftUI: собственные интерфейс, HID-транспорт, последовательный USB-транспорт экрана и работа с локальными файлами.
- `resources/branding/`: новый знак с акулой, созданный встроенным imagegen без референсов производителя; запрос сохранён рядом с изображением.
- `resources/keys.json`: аппаратные идентификаторы клавиш и HID usages, с новой геометрией и обычными обозначениями клавиш. Исходный XML производителя не включён.
- `reverse/device-descriptors.json`: HID-описания, прочитанные с реально подключённой L99; серийные номера и прочие идентификаторы пользователя не включены.
- `core/tests/fixtures/*.hex`: тестовые данные **протокола**, полученные на выходе изолированного сериализатора. Это не машинный код и не прошивка.
- `core/tests/fixtures/*.json`: параметры получения этих тестовых данных. Поле `color` содержит Windows COLORREF (`0x00BBGGRR`).

Оригинальные EXE, DLL, LIB, прошивки, растровая графика, шрифты, языковые файлы, конфигурационные XML и дизассемблированные инструкции в публичную поставку не входят. Локальные материалы исследования хранятся вне папки проекта, предназначенной для публикации.

## Показатели macOS

Сборщики CPU, GPU и температуры написаны для проекта. Используются Mach `host_statistics`, свойство `PerformanceStatistics` в IORegistry и температурные события IOKit. Декларации и номера событий сверялись с Apple IOHIDFamily и публичными исследованиями; сторонние реализации не включались:

- https://github.com/apple-oss-distributions/IOHIDFamily
- https://github.com/fermion-star/apple_sensors

Погодный сервис оригинала и встроенные в него учётные данные не используются и не распространяются. Температура выбрана пользователем как температура Mac, влажность фиксирована на 0%.

Для исследования Music Rhythm локально извлечена вложенная прошивка 1.03 и изолированно проверен её сериализатор 18 уровней экранного спектра на ARM. Прошивка не устанавливалась и не включена в публичные материалы; опубликовано только описание формата обмена.

## Музыка macOS

Захват Core Audio process tap, downmix, FFT через Apple Accelerate, сглаживание, SwiftUI-спектр и управление жизненным циклом написаны для проекта. WASAPI-код, аудиобиблиотеки и графика Windows-программы не переносились. Использованные системные API описаны Apple: [Capturing system audio with Core Audio taps](https://developer.apple.com/documentation/coreaudio/capturing-system-audio-with-core-audio-taps). В поставке нет сторонних аудиодрайверов. Музыкальный fixture содержит только выходные данные протокола из изолированного сериализатора.

## Чтение конфигурации и локальный сеанс

Читатель USB-конфигурации, декодер поддерживаемых действий, сохранение неизвестных записей, упаковка стабильных слотов и атомарное автосохранение написаны для проекта. Формат чтения сверялся с локальным исследованием протокола и проверен на устройстве. Новые тесты используют синтетические таблицы. Снимки пользовательских назначений и сеанс `local-state/` исключены из публичных поставок.


Управление поколениями USB, отмена очереди, сравнение записи с новым чтением и объединение локальных правок с новым снимком в 0.6.0 также написаны для проекта. Их тесты используют вымышленные идентификаторы подключений и синтетические таблицы; в публичные тесты не включён пользовательский профиль.


Расчёт памяти макросов, резервирование отпусканий, восстановление модификаторов по флагам события и передача отдельных счётчиков назначений в 0.7.0 написаны для проекта. Новые тесты используют искусственные таблицы и последовательности событий; пользовательские макросы в исходный архив не включены.


В 0.8.0 состояние редактора назначений с выбором макроса по UUID, конструктор сочетаний и поле проверки ввода написаны для этого проекта. Тесты порядка модификаторов, отдельной адресации Fn и зависимостей назначения используют синтетические данные.


В 0.9.0 область локальной проверки событий, её ограниченный журнал, фон и скрипт упаковки DMG написаны для проекта. Для метаданных окна Finder используются внешние сборочные библиотеки ds_store и mac_alias; они не входят в приложение. В DMG находятся собственное приложение и собственные инструкции, без ресурсов Windows-программы и без пользовательских профилей.

В 0.10.0 механизм локализации, три каталога по 418 сообщений, переводы интерфейса и окно добровольной поддержки написаны для этого проекта. Языковые файлы оригинальной программы не используются. Публичная ссылка Boosty предоставлена автором; платежи открываются во внешнем браузере без платёжного SDK и без обработки данных карты приложением.
